- Booking emails render via `_shared/render-email.ts` (sync `render`), not react-email `renderAsync`. Why: renderAsync can corrupt umlauts at stream chunk boundaries.
- Operational mails stay short: customer mails show only customer prices/status plus a terms link; driver offer and binding-acceptance mails share `_shared/short-offer.ts` and show only the stored net payout. `_shared/operational_mails_test.tsx` renders all variants (OVERVIEW_OUT writes the print overview). Why: one verifiable rule set without sending mail.
- Driver assignment/sending requires offer-readiness evidence plus computable stored net payout before invite/mail writes; failed retries use immutable evidence or are blocked, never replaced with an interest mail. Customer Fernverkehr mails and the booking-form preview (shared `fernverkehrMitWochenende`) show no total when the period contains Sat/Sun. Assignment place = concrete note meeting point, else concrete einsatzort, else complete stored customer address (`resolvedPlace`), otherwise blocked; CE-week daily 329 € may span unbooked weekends only via `ceWeekdaysAcrossWeekends` (Mo–Fr count, no weekday holiday, nothing weekend-booked). Why: preserve snapshots and require confirmed billable units and actual location.
- Every outgoing customer mail stores the exact provider payload via _shared/customer-mail-snapshot.ts in immutable customer_email_snapshots (admin-read only, deletable only after retention_until); legacy email_log rows are shown as content unavailable, never reconstructed. Why: auditable proof of what customers received.
- The first automatic interest offer (`dispatchDriverJobOffers`) shows the driver net via `interestRemuneration`: stored `kosten_uebersicht` driving-service positions minus tariff commission (`commissionPctForTarif`) once, rendered with the shared `renderDriverCompensationBox`; incomplete/unknown tariff, review flag or unbooked weekend positions block the invite and log `admin_actions.driver_interest_offer_blocked`. Why: no priceless or invented offer, no customer prices in driver mail.
- Job release (`admin-approve-job`, incl. "Erneut senden") sends that same interest offer via `dispatchReleasedJobToContractDrivers` to every non-test approved driver with the current accepted contract; `broadcast-job-to-drivers` excludes those drivers and test drivers, test jobs/drivers never get automatic offers. Why: contract drivers always get the net pay, never the priceless broadcast or a duplicate.
